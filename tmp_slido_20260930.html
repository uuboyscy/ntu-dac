01求職與職涯

剛剛聽學長分享時，有提到幾份工作機會是透過獵頭牽線，想請問學長當初是怎麼接觸到這些獵頭的呢？是透過 LinkedIn 主動 connect，還是有其他比較推薦的管道或資源？

定時更新 LinkedIn，有工作經驗後就會有獵人頭主動聯絡

02AI 與工作方式

請問學長覺得自己的工作內能被取代/不能被取代的部分是什麼

  • 能被取代：寫程式、可被定義的重複性工作
  • 還不能被取代：團隊溝通、理清人類留下的技術債
03AI 與工作方式

請問根據學長的經驗 各產業應用AI的情況有差異嗎 都是負責較基礎加速的部分嗎～

跟管理層願不願意推動有關，絕大多數都還是用 AI 做基礎加速、做重複性工作(甚至是本來就可以簡單寫程式重複執行的工作)。

但有些公司已經架設自己的 Agent，自動測試、自動 review，甚至有 Agent 會做比較簡單的自動開發，收到 ticket 先自動產出初步結果。

04DE 技能準備

如果未來想往資料工程師的方向發展，想請問學長會建議技能樹怎麼點比較好？如果是從基礎開始準備，會建議先從哪些技能開始學，再逐步延伸到哪些工具或能力呢？

  1. 如何用 SQL 或 Python 處理資料，可以直接參考 LeetCode 的資料處理題目(SQL & Pandas)
  2. 嘗試畫資料流，猜猜看報表的原始資料可能有哪些、可能長什麼樣子、可能會遇到什麼問題。現在可以用 AI 輔助。
05資料治理與工具

剛剛提到資料血緣可以用圖表的方式畫出關聯，想請問如果這些資料中間有經過計算、整合等，要怎麼標示出來，還是有其他整理這些資料文件的方法

產生數據血緣的工具通常都會附帶這個功能，比較熱門的開源工具是 dbt(專門管理大量 SQL 的工具)，同時可以看到每一個欄位經過什麼測試，甚至可以產生一個類似搜尋引擎的網頁，讓分析師查詢有哪些 metric 可以用

06工作內容與挑戰

想請問學長，擔任資料工程師時，在工作內容上有哪些比較有挑戰，或是實際做過之後覺得比較辛苦、不太喜歡的地方嗎？

比較辛苦的是跟非工程背景的人解釋資料處理過程遇到的問題，例如為什麼沒辦法及時補資料、為什麼某個報表不能一天做完。

挑戰的話，前期偏工程的工作是 debug 很有挑戰，後期是規劃出一個夠簡單，連非工程人員都能看懂的架構很有挑戰。

07求職與職涯

想問學長在換工作的時候，會設定說自己大概做到什麼樣的目標就該離職了嗎? 如何有效規劃自己離職跟跳去下一份工作的時間點?

其實我沒有特別設定目標，但是通常一個大專案做完就剛好會有獵人頭找我，運氣成分偏重
